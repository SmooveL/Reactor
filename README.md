# Reactor (Золотое Яблоко)

Инструмент автоматизации подачи жалоб на фишинговые ресурсы, имитирующие «Золотое Яблоко» (`goldapple.ru`). Вставляете мошенническое сообщение или ссылку — инструмент собирает данные о домене, отправляет URL в API блок-листов, готовит письма регистратору и хостеру и открывает предзаполненные формы вендоров.

```bash
./run.sh
# или на Windows:
python server.py
```

Открывает локальный веб-интерфейс на `http://127.0.0.1:8420` (только localhost, наружу не выставляется).

## Что изменено (модернизация под «Золотое Яблоко»)

- **Русский интерфейс и уведомления:** переведены все вкладки (`Жалоба`, `Настройки`, `История`), сообщения сервера (`server.py`, `status.py`, `notify.py`), пояснения к вендорам (`sites.py`) и каналам (`channels.py`). Названия сервисов и технические статусы API (`SKIP`, `FAIL`, `confirmed`) оставлены без перевода, письма зарубежным регистраторам и хостерам формируются на английском.
- **Единственная цель — «Золотое Яблоко»:** удалён выбор сторонних брендов из интерфейса, `BRAND_HINTS` и `BRAND_ABUSE`; отключена копия письма службе безопасности бренда. Во всех письмах, комментариях и рецептах используется `Золотое Яблоко (goldapple.ru)`. Если на форме вендора в списке брендов нет «Золотого Яблока», выбирается «Другое» / `Other`, а бренд добавляется в комментарий.
- **Защита официальных доменов:** в `config.json` добавлен список `legit_domains` (`goldapple.ru`, `goldapple.kz`, `goldapple.by`, `goldapple.sa`, `goldapple.qa`, `goldapple.ae`). Жалобы на официальные домены и их поддомены блокируются в интерфейсе, API и CLI. Проверяется точное совпадение хоста: `goldapple.ru.fake-site.top` официальным не считается. Если ссылка и текст не похожи на «Золотое Яблоко», показывается предупреждение без блокировки отправки.
- **Разбор русскоязычных сообщений:** в `intake.py` расширен список доменных зон (`.kz`, `.by`, `.sa`, `.ae`, `.qa`, `.su`, `.рф` и др.), добавлена поддержка кириллических доменов и обфускации `(точка)`, а также русские признаки мошенничества (`LURES`).

## Установка

Требуются Python 3 и Chromium через Playwright.

```bash
python3 -m venv .venv
source .venv/bin/activate   # на Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
playwright install chromium
cp config.example.json config.json
python server.py
```

API-ключи, почтовые настройки и список `legit_domains` хранятся в `config.json` (настраивается также через вкладку **Настройки**). Файл `config.json` добавлен в `.gitignore` — никогда не коммитьте API-ключи, SMTP-реквизиты, профили браузера или сформированные отчёты.

## Вставляйте сообщение, а не ссылку

Шаг 1 на вкладке **Жалоба** — поле, в которое вставляется текст мошеннического SMS, письма или сообщения целиком. Инструмент:

- извлекает все ссылки, включая формы `hxxps://`, `[.]`, `(dot)`, `(точка)`, `{.}` и домены в зонах `.ru`, `.kz`, `.by`, `.sa`, `.ae`, `.qa`, `.su`, `.рф`, `.top`, `.shop` и др.
- распознаёт русские и английские признаки мошенничества (срочность, угроза блокировки, розыгрыш/бьюти-бокс, фейковая доставка или возврат, выманивание кода/пароля/карты)
- автоматически блокирует официальные домены «Золотого Яблока» из `legit_domains` и предупреждает, если ссылка не похожа на бренд
- раскрывает только известные сокращатели ссылок — обычные фишинговые ссылки на этом этапе не запрашиваются
- помечает хосты, по которым жалобы уже подавались

Отметьте нужные цели и нажмите **Отправить все отмеченные**: выполнятся разведка, отправка в API блок-листов и генерация черновиков писем. Формы вендоров открываются по одной ссылке — используйте кнопку **В шаг 2**.

## Что делает одно нажатие

| Этап | Что происходит | Автоматически? |
|---|---|---|
| Разведка (Recon) | RDAP + DNS: регистратор, дата регистрации, хостинг-сеть, опубликованные abuse-контакты | да |
| API блок-листов | Netcraft, urlscan.io, VirusTotal | да |
| Письма жалоб | Регистратору, хостингу/сети, в APWG и Netcraft fallback (зарубежным адресатам на английском) | всегда черновики `.eml`; автоотправка при настроенном SMTP |
| Формы вендоров | 15 вендоров открываются **параллельно** (по 5 за раз), заполняются поля, выбираются категория угрозы и бренд («Другое» при отсутствии ЗЯ), воспроизводятся рецепты | заполняется + классифицируется; **Отправить все** отправляет формы без CAPTCHA |
| История | Одно дело на цель (`reports/<хост>/case.json`) — доказательства для последующей жалобы в ICANN | да |

## Обучение (рецепты автозаполнения)

Пока вкладки форм вендоров открыты, инструмент записывает ваши действия по каждому сайту в `recipes/<site>.json`. При следующем запуске эти шаги воспроизводятся до того, как управление вернётся специалисту.

Запись включается **только пока вкладка находится в руках специалиста**. Драйвер отключает её во время собственного автозаполнения, чтобы рецепты не засорялись.

### Перенос рецептов между разными фишинговыми доменами

Каждый записанный шаг при сохранении помечается типом переноса, чтобы прошлый фишинговый домен не попал в новую жалобу:

| Метка | Пример | При следующей жалобе |
|---|---|---|
| `threat` | «Phishing», «Malicious site» | воспроизводится как есть |
| `brand` | «Золотое Яблоко (goldapple.ru)» | выбирается в списке брендов, при отсутствии — «Другое» / `Other` с добавлением бренда в комментарий |
| `target` | «goldapple-prize.top» | подставляется заново из нового URL |
| `sticky` | «Retail» | воспроизводится и помечается в колонке *Проверить* |

Свободный текст токенизируется на уровне подстрок: строка `Фишинг Золотое Яблоко (goldapple.ru) на goldapple-prize.top` сохраняется как `Фишинг {{brand}} на {{domain}}` и при следующем запуске подставляет уже новый домен. Рецепт, в котором остался старый домен цели, проваливает самопроверку.

- Пароли никогда не записываются.
- Длинный нераспознанный текст (>120 символов) сохраняется как `{{typed}}` — поле запоминается, сам текст нет.
- Нажатие кнопки отправки (`Submit`) намеренно не воспроизводится из рецепта.
- На вкладке **История** показаны все сохранённые рецепты с кнопкой **Забыть**.

## Двухэтапные формы

У части вендоров сначала выполняется поиск URL, и только потом открывается форма с выбором категории угрозы. Одно нажатие **Отправить все** продвигает процесс на один этап: инструмент кликает, находит новую форму, заполняет её и просит нажать ещё раз.

## Встроенные правила

- **Никогда не жалуется на официальные домены «Золотого Яблока».** Домены из `legit_domains` и их поддомены жёстко блокируются на уровне разбора, API, писем и форм.
- **При заполнении форм вендоров не открывает сам фишинговый сайт.** URL вводится текстом в формы вендоров.
- **Не решает CAPTCHA.** Формы с CAPTCHA определяются автоматически и отправляются специалистом вручную.
- **Ничего не отправляется до нажатия «Отправить все»** с диалогом подтверждения.
- **Не заявляет «подано» без подтверждения сайта.** Одной текстовой фразы недостаточно — кнопка отправки должна исчезнуть. Иначе результат помечается как требующий проверки, а не `confirmed`.
- **Не принимает условия использования за специалиста** (например, ToS у Symantec).
- Браузер форм работает в отдельном профиле `.browser-profile/` без ваших рабочих сессий и cookies.
- API-ключи и пароль SMTP хранятся только в `config.json` (в Git не попадают).

## Состояние форм вендоров

Заполняются автоматически и ожидают подтверждения: Google Safe Browsing, Microsoft SmartScreen, Fortiguard, BrightCloud, CRDF, Netcraft, Palo Alto, ESET, Trend Micro, McAfee/Trellix, Spam404.

Открываются с дополнительным ручным шагом (причины указаны в подсказках интерфейса):

- **Symantec** — сначала требует принять условия использования
- **Cisco Talos** — проверка Cloudflare на ботов
- **Kaspersky OpenTIP** — поиск предзаполнен URL; отправка вердикта требует бесплатного аккаунта
- **Bitdefender** — страница с инструкцией, без прямой формы (почта `submit@bitdefender.com`)
- **Forcepoint CSI** — выключен по умолчанию (`csi.forcepoint.com` не резолвится)

## Почтовые аккаунты для жалоб

На вкладке **Настройки** хранится список адресов отправителя, а на вкладке **Жалоба** можно переключать активный аккаунт. Он подставляется в формы вендоров, в поле `From:` черновиков и в ссылки Gmail.

Ссылка Gmail выбирает аккаунт **по адресу** (`authuser=`), поэтому поле **Слот Gmail** обычно оставляют пустым. Плюс-алиас (`you+abuse@gmail.com`) сводится к базовому ящику автоматически. Если настроен глобальный SMTP и его логин не совпадает с активным адресом, интерфейс предупредит об этом.

## История и проверка статуса

По каждому фишинговому ресурсу ведётся дело в `reports/<хост>/case.json`: разведка, ответы API, черновики писем, статусы форм вендоров и хронология проверок. Запись выполняется сразу при получении каждого результата.

Кнопка **Проверить статус** собирает пять сигналов без прямого захода на сайт:

- **Реестр (RDAP)** — статусы `clientHold`/`serverHold` (авторитетное снятие домена)
- **DNS** — резолвится ли хост и не изменились ли NS-серверы
- **Google Safe Browsing** — предупреждает ли Chrome посетителей (нужен бесплатный ключ)
- **urlscan.io** — наличие сканов и вердикт сообщества
- **VirusTotal** — количество срабатываний движков (нужен бесплатный ключ)

Кнопка **Проверить + открыть HTTP** добавляет прямой запрос с вашего IP (выключено по умолчанию, за диалогом подтверждения).

Вердикты: `suspended` (приостановлен регистратором), `offline` (не резолвится, но домен ещё зарегистрирован), `blocked` (предупреждение браузера/Cloudflare или ошибка сервера), `live-flagged` (работает, но уже в блок-листах), `live` (работает, не помечен), `unknown` (недостаточно данных).

### Автомониторинг

На вкладке **Жалоба** блок **Текущий статус целей** обновляется каждые 10 секунд. При включении **проверять автоматически** сервер по таймеру перепроверяет открытые дела (по умолчанию раз в 15 минут).

## Связанные кампании

На вкладке **История** дела с общими признаками инфраструктуры группируются в кампании (общий Cloudflare игнорируется) и формируется сводная жалоба регистратору.

## Мониторинг новых доменов-имитаций (Certificate Transparency)

Блок на вкладке **Жалоба** опрашивает публичные логи сертификатов (`crt.sh`) по ключевым словам из `ct_keywords` (по умолчанию `goldapple, gold-apple`) и оценивает похожие домены без обращения к ним. Хостинг-платформы вроде `*.workers.dev` и `*.pages.dev` обрабатываются с сохранением поддомена арендатора.

## Уведомления и буфер обмена

- **Уведомления на рабочем столе** (macOS) срабатывают только при значимых сменах статуса дела, появлении нового похожего сертификата и открытии окна эскалации в ICANN.
- **Мониторинг буфера обмена** (выключен по умолчанию) перехватывает скопированные ссылки; сам текст буфера не сохраняется и не логируется, официальные домены «Золотого Яблока» отфильтровываются.

## Эскалация в ICANN и пакет доказательств

- **Жалоба в ICANN** проверяет готовность (письмо регистратору отмечено отправленным, прошло 24 часа, домен не приостановлен) и собирает текст обращения со ссылками на хронологию.
- **Пакет доказательств** собирает архив `reports/<хост>/<хост>-evidence-<timestamp>.zip` с файлами `report.html`, `checks.csv`, `case.json`, скриншотом (если есть в urlscan.io) и `.eml`-черновиками.

## Национальные каналы жалоб

На вкладке **Настройки** можно подключить национальные каналы из `channels.py` (CERT, регуляторы, горячие линии). Для каждой записи фиксируется способ и результат проверки (`verified`).

## Файлы

- `server.py` — локальный веб-сервер и API
- `ui.html` — веб-интерфейс на русском языке
- `reactor.py` — разведка (RDAP/DNS), API блок-листов, генерация `.eml`, защита `legit_domains` (также CLI: `python reactor.py <url> --send`)
- `intake.py` — разбор сообщений, извлечение ссылок, русские признаки фишинга и проверка доменов
- `automate.py` — драйвер Playwright, классификатор полей, выбор бренда и рецепты
- `sites.py` — список площадок вендоров и подсказки на русском
- `channels.py` — национальные каналы жалоб
- `casefile.py`, `bundle.py`, `escalate.py`, `campaigns.py` — хранение дел, пакет доказательств, ICANN и кампании
- `status.py`, `notify.py`, `ctwatch.py`, `gmailslots.py` — проверка статуса, уведомления, CT-мониторинг и Gmail-слоты
- `config.example.json` — шаблон настроек (рабочий `config.json` в Git не попадает)
- `reports/` — дела, черновики `.eml`, `runs.jsonl`, `log.jsonl`
